# 評価の定石 — 3層評価・リーク検査・統計的判定・診断（loop9/10実証）

## 評価3層（DAPT系はmust・SFT/GRPOでも②③は常に）

3層は**それぞれ別の答えを返す**（loop10: ①PASS ②FAIL ③TIE）。1指標で合否を語らない。

| 層 | 測るもの | 方法 |
|---|---|---|
| ① held-out corpus loss | 分布適応（文体・語彙への馴染み） | 学習外 val 文書の CE を base vs 学習後で直接比較。**NeMo finetune は学習中validationを走らせない**ので、オフライン測定が正（nemo コンテナで transformers 直ロード・4096窓CE平均・GPU1枚~10分） |
| ② 非退行（忘却検査） | 既存能力の維持 | 既存評価を `BASELINE=<過去タグ>` 付きで再実行。**絶対閾値でなく過去実測との相対比較**（根拠のない絶対閾値0.85はloop8で廃止済み） |
| ③ 能力の階段 | 狙った軸の上積み | タスク評価（eval/eval-finqa）または knowledge-probe。**baseが弱い軸を意図的に選ぶ**（baseが強い軸は天井で階段が出ない） |

### knowledge-probe の設計（DAPT知識注入の測定）

- probe種文書は**学習コーパス内**のサブセットにする（除外すると汎化テストになり注入知識を測れない — loop10で設計訂正済み）
- 教師生成の質問は closed-book で自立するよう**会社名・固有名詞を質問文に明示**、答えは短い事実
- 採点はローカル（数値=相対誤差1%・文字列=正規化包含）で API 課金なし
- **同点が出たら配信切替を検証**: 両モデルの pred に相違があるか確認（相違があれば真の同点。loop10は56問相違で確定）

## リーク検査（must — これなしの評価は無効）

- 学習コーパス × 既存 heldout を **30字シングル（stride 15＋末尾窓・空白正規化）** で照合し、
  ヒットした学習文書は**除外**（heldout側は不可侵なので触らない）
- loop10 実績: **223文書の実リークを検出**（既存heldoutがEDINETチャンク由来で同じ有報がコーパスに居た）。
  「別ソースだから大丈夫」は通用しない
- SFT/GRPO/heldout の3セット排他も同様（正規化質問文で照合・違反=ビルド失敗にする — loop9実装）
- heldout は学習・報酬・プロンプト例に使わない。評価母数を増やすときは評価専用の別ファイル
  （heldout_ext 方式）にし、全splitと重複排除する

## 統計的判定（差の解釈）

- 二値正解率の SE ≈ √(p(1−p)/n)。**n=300 で ±0.02-0.026、n=70 で ±0.05**
- 差が SE 内なら「同等」。改善とも退行とも言わない（loop9: grpo9kl +0.0013 は「baseと同等」が正しい読み）
- n が小さい評価（n=28 では1件=3.6pt）で1-2件の差を根拠に判断しない。まず評価母数を増やす

## GRPO診断の定石（②③はGPU課金ゼロ — 追加課金の前に必ずやる）

1. **帯域診断ゲート（起動時must）**: max_num_steps=3 で起動し step1-3 の Avg Reward が 0.5-0.9・
   グループ内分散あり（pct_0/pct_1/pct_mixed 共存）を確認。0.0x台=形式未習得か全滅、0.95超=暗記済み。
   外れたら**GPUを止めて**データ難易度を再調整
2. **train reward 推移**: `grep "Avg Reward"` で first30 vs last30。横ばい=学習が押し上げていない
3. **item単位 fix/break 差分**: eval details を index結合し、base誤答→正答（fix）と base正答→誤答（break）を数える
   - fix > 0 = 学習可能シグナル実在（base天井ではない）
   - **break > fix = KLなしドリフトの signature** → KL有効化+lr調整
   - **fix ≈ break = 天井の signature** → 手法/タスクを変える（decision-table.md）

この3点で「config弱い / base天井 / drift」を切り分けてから、次のGPU課金を提案する。
