# ループ12 設計書 — NeMo Retriever（RAG）vs DAPT知識注入の費用対効果比較

作成: 2026-08-08（設計フェーズ・課金操作なし）。承認ゲート通過後に実装・実行へ進む。

## 1. 目的と位置づけ

loop10 の最終結論（docs/loop-10-report.md §3）:

- full-param DAPT 1epoch は分布適応（held-out ppl −10.6%）を起こすが、**closed-book で取り出せる知識は入らない**（probe QA 199問: dapt10 0.0402 = base10 0.0402 の完全同点）
- DAPT で知識注入を狙うなら多epoch×パラフレーズ増幅 + SFT形式回復が前提。**ただしその前に RAG（検索で文書を渡す）との費用対効果比較が先**（decision-table.md にも定石として登録済み）

→ loop12 はこの問い **「その知識は本当に重みに入れる必要があるか？」** に実測で答える。
loop10 が作った評価資産（probe QA 199問・closed-book 0.0402 という低い base 実測）は
「baseが弱い＝伸びしろのある軸」（loop9 教訓）そのものであり、RAG の階段を測る物差しとして最適。

### 教材としての目標（NeMo 未消化コンポーネントを通す）

| コンポーネント | 状態 | loop12 での消化 |
| --- | --- | --- |
| **NeMo Retriever**（text embedding / reranking NIM） | 未消化 | EDINET コーパスのインデックス構築と検索を NIM で実行（P2/P3） |
| S7 Guardrails | 未消化 | 今回は対象外（loop13 以降の候補として残す） |

## 2. 現状の資産と不足

**資産（すべて loop10 で構築済み・再課金ゼロで再利用）**:

- `data/pretrain/corpus_train.jsonl` — curated 2,530文書・8,924万字（リーク検査済み）→ **RAG の検索対象コーパス**
- `data/pretrain/corpus_probe.jsonl` — 追跡50文書（コーパス内）
- `data/pretrain/probe_qa.jsonl` — 教師生成 199問。質問文に会社名を明示する設計（= 検索クエリとして機能する）で、**gold の出典 doc_id 付き → 検索品質（recall@k）を独立に採点可能**
- `s6_evaluation/probe_qa.py` — closed-book 評価＋ローカル採点（数値=相対誤差1%・文字列=正規化包含）。API 課金なし
- base 実測: closed-book 0.0402（base10 = dapt10、pred相違56問で真の同点と検証済み）

**不足（loop12 で作るもの）**:

- チャンク化＋インデックス構築（`s8_retrieval/` 新設）
- 検索→文脈注入→生成→採点の RAG 評価ハーネス（`probe_qa.py` の open-book モード拡張）
- 検索品質の独立評価（recall@k / MRR）

## 3. 比較設計 — 費用対効果の枠組み

**DAPT 知識注入路線は今回実走しない。** loop10 実測値からの見積りで比較し、RAG 側だけ実測する
（比較の答えを最小コストで出す設計。DAPT側を走らせるのは「RAGが負けた場合」だけでよい）。

| 軸 | DAPT 知識注入路線（見積り） | RAG 路線（loop12 で実測） |
| --- | --- | --- |
| 初期コスト | 多epoch(3-5)×$75 + パラフレーズ教師API + SFT形式回復 ≈ **$300-550** | インデックス構築＋評価 ≈ **$15-30** |
| 効果の確度 | 未実証（1epは完全同点。多epochでも定着量は不明） | 検索が当たれば読解問題化（baseの得意領域） |
| 忘却リスク | あり（loop10 ②で実証: −0.115/−0.041 退行 → SFT回復が別途必要） | **ゼロ**（重み不変） |
| 知識の更新 | 有報は毎年更新 → 都度再学習 | 文書追加＝インデックス追記のみ |
| 推論時コスト | なし | embedding/rerank の常駐 or 都度起動＋レイテンシ |

RAG が probe で明確に勝てば「知識=RAG / 分布適応=DAPT / 形式=SFT / 仕上げ=GRPO」の役割分担が完成し、
DAPT 多epoch知識注入路線はクローズできる。

## 4. パイプライン設計

### P1 実装＋dry 配管（$0・ローカル）

- `s8_retrieval/` 新設:
  - `chunk_corpus.py` — corpus_train.jsonl → チャンク（800字・stride 400 目安 → 約20万チャンク。doc_id 保持）
  - `build_index.py` — embedding → numpy/FAISS フラットインデックス（20万×1024次元 ≈ 0.8GB、総当たりで十分。
    Milvus 等のベクトルDBは可動部を増やすだけなので不採用と明記）
  - `retrieve.py` — クエリ埋め込み → top-k → （任意）rerank → 文脈整形
- `probe_qa.py` に `--rag` モード追加: 検索文脈をプロンプトに前置して同一199問・同一採点で評価
- `Makefile`: `retriever-index` / `retriever-recall` / `rag-eval` と各 `-dry`（数文書・ダミー埋め込みで配管確認）
- ユニットテスト: チャンク境界・doc_id 追跡・採点の回帰（デバッグを GPU 時間から切り離す — loop10 教訓）

### P2 配管検証（GPU小・承認ゲートA）

- ノードで **NeMo Retriever embedding NIM**（`llama-3.2-nv-embedqa-1b-v2`・多言語対応・L40S可）を起動
  - **前提: NGC API キー（無料・ユーザー登録作業）**。取得不可/NIM不動の場合のフォールバックは
    HF `intfloat/multilingual-e5-large`（MIT）直ロード — 教材目標は縮小するが比較実験は成立
- probe 50文書のみインデックス → recall@5 サニティ → base 配信 + RAG 20問の一気通貫
- ここで確定する技術判断: NIM の可否 / 日本語有報での埋め込み品質の初見 / rerank NIM の要否

### P3 本走（GPU・承認ゲートB）

  3. （任意・recall が低い場合のみ）rerank NIM 追加で再評価
- dapt10+RAG は原則やらない（dapt10 は形式退行があり RAG の土台として不利。§7 の判定に不要）

## 5. 評価設計（3層の loop12 適用）

| 層 | 物差し | 判定 |
| --- | --- | --- |
| ① 検索品質 | recall@5 / MRR（gold doc_id、n=199） | **recall@5 ≥ 0.7** で検索は成立。< 0.3 ならチャンク/embedding を1回だけ調整 |
| ② 生成品質（階段） | RAG probe 正解率 vs closed-book 0.0402 | n=199 の SE ≤ ±0.035。**≥ 0.4（10倍）で RAG 優位確定** |
| ③ 非退行 | — | **原理的に不要**（重み不変・評価時のみ文脈注入。配信構成は base のまま）。省略の根拠として明記 |

- ①と②を分離するのが肝: 「recall 高 × 正解率 低」= 読解・抽出の問題（→ grounded QA の SFT が次ループ候補）、
  「recall 低」= 検索の問題（→ チャンク・embedding・rerank）。1指標で語らない原則の踏襲
- リーク検査について: RAG は**コーパス内文書を意図的に渡す** open-book 評価なので、loop10 の
  closed-book リーク規律とは目的が異なる。heldout（finqa/analysis）は今回一切触らない
- バイアスの明記: probe QA は「質問文に会社名明示」設計のため検索に有利。これは実運用（ユーザーが
  会社を特定して聞く）に沿った意図的設計だが、総括に明記する

## 7. リスクと撤収基準

- **NIM が使えない**（NGCキー未取得/L40S不適合/イメージ不良 — loop10 罠7の前例あり）→ HF embedding に
  フォールバックして続行。「NeMo Retriever NIM の消化」は縮小し、その旨を総括に記録
- **recall@5 < 0.3**: チャンクサイズ/オーバーラップ/クエリ整形の調整を**1回だけ**試行。
  それでも低ければ「日本語有報 × このembeddingでは検索不成立」を実測結論として総括（負の結果も成果）
- **recall 高 × 正解率低**: 撤収ではなく分岐。「知識はコーパスにあり検索も当たるが、抽出読解で落ちる」
  → grounded QA SFT（RAG前提の形式学習）を loop13 候補として提案
- **判定のグレーゾーン**（正解率 0.1-0.4）: 部分優位。誤答の item 単位分析（検索ミス/読解ミス/採点厳格）で
  内訳を出してから次を判断
