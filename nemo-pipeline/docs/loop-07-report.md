# 学習ループ 7周目レポート（2026-07-21）

## 1変更の内容（sft6 の SFT 逆効果 = 訓練分布への対処）

**的絞りデータ増強**（PR #26、`s2_distill.py --augment` / `make augment`、教師 ~$0.5）:

SFT が訓練分布の疑似相関を増幅する構造（ループ3・4・6で3回再現）への根治策として、
不足パターンの訓練例を教師生成し **train/valid にのみ** 追記した（heldout 不可侵）。

| パターン | 採用/生成 | 狙い（sft6 失敗との対応） |
|---|---|---|
| summary_dated（日付付き全体要約） | 13/15 | summary+本日→date_range=null 疑似相関の反転（i21, i23） |
| week_range（「今週」範囲） | 15/15 | 訓練2件のみで規約(3)月曜始まりが上書き不能だった（i26） |
| comparison_pair（商品名ペア比較） | 6/15 | sectors=["overall"] 逃げ再発の対策（i6） |

- 過学習ガード: heldout は重複排除の参照のみで不読不写・追加34件（train の~13%）・
  全 split との dedup・規約リント違反ラベルは即棄却
- **リントゲートの副産物**: comparison_pair の棄却9件は「教師自身が商品ペア比較で
  単一セクター/overall 逃げをした」ものをリントが検出 — 生徒の失敗パターンの出所が
  教師の生成分布にもあった証拠
- 基準日は既存 label_today（2026-07-19）と強制整合（混在すると s6_eval が
  実行日フォールバックし相対日付ゴールドが崩れる）

## 所見

1. **SFT の逆効果が止まった（今回の最重要成果）**: sft6 は base から −0.035 の逆転負け
   だったが、sft7 は base7 と同値 0.821。3ループ連続で再現していた「SFT が訓練分布の
   疑似相関を増幅する」構造が、分布への直接介入で反転した
2. **増強の的中箇所**: comparison 1.0 回復（overall 逃げ消滅）、summary の
   schema/sectors/qt 全て 1.0（sft6 で2件だった summary→null は1件に半減）、
   i26 の query_type 劣化（trend→summary）も解消。過学習の兆候なし
   （増強対象外の ambiguous 1.0 / edge 0.5 / single_sector 0.875 は base7 と同値）
3. **sft7 残failure 5件の構図**: (i9,i12) edge 架空商品→gold overall vs pred `[]` ×2 /
   (i16) 曜日計算（今週火曜→7/8。SFT でむしろ悪化方向）/ (i21) summary+本日→null 残存 /
   (i26) 今週開始 7/12（qt は治ったが dr は15件の訓練例でも未矯正）。
   **5件中3件（i16, i21, i26）が date_range 起因** — 暦計算・日付規則は SFT の
   模倣学習では上書きしきれないことが今回で確定的になった
4. **閾値まであと1件**（23/28、閾値 0.85=24/28）。データ増強・プロンプト規約という
   「教師データを良くする」レバーは今回でほぼ使い切り、残る失敗は
   (a) date_range の計算能力、(b) edge の gold 規約 vs モデル素直解釈（`[]`）の2種に収束

## 運用メモ（今回のトラブルと対策）

- **node-start.sh 実機初検証で不具合発見→修正**（PR #27）: `aws s3 sync` は壊れた
  symlink のスキップ警告だけで rc=2 を返し、`set -e` で data 同期以降が静かに中断
  していた。rc=2 許容の `s3sync()` ラッパーで修正（次回起動時に再検証）

  使い切り、convert-sft のマージ書き出しで失敗。loop1〜3 アーカイブを削除して復旧。
  **今後はアーカイブ保持は直近2世代のみ**（SFT 前の退避時に3世代前を削除する）
- ループ7 ckpt はノード checkpoints/sft/{step_30,hf}、アーカイブは loop4〜6 の3世代
  （次回退避時に loop4 を削除）
- コスト: GPU ~$2-3（見積どおり）+ 教師 ~$0.5

## 次周（ループ8）候補 — 1変更の原則

主目標は analysis_match 0.821 → 0.85（あと1件）。所見3のとおり残失敗は SFT で
届かない領域に収束したため、次の一手は学習方式そのものに踏み込む:

1. **S5 GRPO（date_range 検証可能報酬）を推奨**: 残5件中3件が date_range 起因で、
   reward.py の検証可能報酬で直接罰する GRPO が唯一この領域に効く手段。
   曜日計算（i16）・今週開始（i26）・summary→null（i21）が全て対象。
   コスト・不安定性リスクは SFT より高いため、まず小規模（低 step・小 lr）で試す
2. edge の的絞り増強（架空商品→overall の見本を train に追加）: 残る非 dr 失敗2件
   （i9, i12）の対策。ただし増強レバーの限界効用は今回で見えており、GRPO 後に検討
