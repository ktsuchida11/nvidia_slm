# NeMo SLM パイプライン ハンズオン

## 自分の手で一周回す

社内勉強会 第2回 / 2026-XX

---

## 今日のゴール（3つ）

1. **パイプラインを自分の手で一周させる**
   S1 クレンジング → S2 蒸留 → S8 RAG → S7 ガードレール → スキル

2. **各 Step で1回ずつ「壊してみる」**
   動かすだけなら手順書で足ります。**壊れ方を見た人だけが、
   自分のデータを入れたとき判断できます**

3. **帰ったら自分のデータ10件で `make curate` を通せる状態になる**

---

## 進め方のルール

- 手元の **`37-handson-runbook.md`** がコピペ用の正です。
  `$` で始まる行をそのまま貼れば進みます
- 各 Step の最後に **【完了定義】**（画面に出るべき数字）があります。
  出たら次へ。**出なければ挙手** — 数字が違うのは大抵ローカルの差分です
- 詰まったら runbook 末尾の「**困ったときの早見表**」を先に見てください
- 今日は **GPU も API キーもネットワークも不要**です（Step 6 を除く）

## Step 0. 環境確認（いまここ）

事前課題の確認。これが出れば準備完了です:

```bash
$ docker run --rm python:3.12-bookworm python -c "print('ok')"
ok
```

出ない場合の3パターン:

| 症状 | 対処 |
| --- | --- |
| `permission denied`（Linux） | `sudo usermod -aG docker $USER` → 再ログイン |
| Windows | WSL2 の中で実行（`make` が要ります） |
| プロキシで pull 不可 | 講師からイメージ tar を受け取り `docker load` |

イメージのビルドは不要です。今日のスクリプトは **Python 標準ライブラリだけ**で動きます。

## 復習: パイプラインの中の「今日やる範囲」

```
S0 評価設計 → S1 収集・キュレーション → S2 蒸留 → S3 DAPT
→ S4 SFT → S5 GRPO → S6 評価 → S7 ガードレール → S8 RAG
```

- 今日触るのは **S1 / S2 / S8 / S7 + スキル**（リソースが軽い順に並べ替え）
- 第1回の要点: **手法は目的で選ぶ**（知識=RAG / 形式=SFT / 安全=Guardrails）
- 学習系（S3-S5）は Step 6 でのみ。**GPU トラブルに前半を巻き込ませない**設計です

# Step 1. S1 クレンジング（30分）

## 何が捨てられるかを見る

---

## Step 1 やること: 6件入れて2件しか残らない

サンプル6件を作って `make curate-demo` → `stats.json` を読む:

```json
{"kept": 2, "rejected": 3, "fuzzy_dropped": 1,
 "pii_masked": {"EMAIL": 1, "PHONE_JP": 1}}
```

捨てた理由は**全件記録**されています（`rejected.jsonl`）:

```
exact_dup        | 昨日の原油価格は上昇。WTIは…
too_short        | asdf!!!! ????
license:cc-by-nc | 商用不可サンプル。金銀相場の説明。
```

語尾だけ違う近似重複も `fuzzy_dropped` で落ち、
残った2件ではメール・電話番号が `[EMAIL]` `[PHONE_JP]` にマスクされます。

---

## Step 1 演習: 自分で1件足して、狙った理由で落とす

`data/demo_raw/sample.jsonl` に1行足して `make curate-demo` をやり直す:

| お題 | 期待する結果 |
| --- | --- |
| `"license":"cc-by-nd"` にする | `reject_reason` が `license:cc-by-nd` |
| 本文を20文字未満にする | `too_short` |
| 既存の文の語尾だけ変える | `fuzzy_dropped` が増える |
| メールアドレスを本文に入れる | **落ちずに** `[EMAIL]` にマスク |

**【完了定義】**: 自分が足した1件が、狙ったとおりの理由で落ちた（またはマスクされた）

---

## Step 1 考えどころ

> 自社のデータを入れたら、何件残ると思いますか？

このプロジェクトの実データでは 2,551文書 → 2,530文書（PII 89件マスク・fuzzy 22件除去）。

そして罠をひとつ: **NeMo Curator の非英数字フィルタは英語専用**です。
日本語は74%が非英数字なので、素直に使うと**全滅**します。

**海外製ツールの既定値は日本語を想定していない** — 自分のデータで最初に疑う場所です。

# Step 2. S2 蒸留（30分）

## 学習データの作り方と、その落とし穴

---

## Step 2 やること: 配管を通して3分割を見る

`make distill-dry` — 教師 LLM は**一度も呼びません**（API キー不要・$0）:

```
[distill] INFO done: {'total': 400, 'train': 322, 'valid': 39, 'heldout': 39, ...}
[distill] INFO ★ heldout.jsonl は学習・GRPO報酬に使わないこと(評価専用)
```

- 出力は `data/distilled_dry/` — 実データは壊れません
- **`heldout` は評価専用の聖域**です。学習にも報酬にも絶対に使わない。
  ここが汚れると、以降すべての数字が意味を失います

---

## Step 2 演習（本題）: 教師データの欠陥を探す

このプロジェクトの1周目で実際に起きた事故の追体験です。

> **generation の学習データ 17/17件すべてが「レポートに記載がありません」だった。**
> 文書（企業の沿革）と質問（市況の見通し）が噛み合わず、
> 教師 LLM は**正しく**「記載なし」と答えていた。

評価するまで誰も気づきませんでした。**蒸留直後に目視すれば5分で分かった**ことです。

runbook 2-3 のコマンドで質問を10件表示して、「**この質問はその文書から答えられるか**」を
目視判定してください。

**【完了定義】**: 3分割の件数が出て、`heldout` と `train` に同じ質問が無いことを確認した

> 実課金オプション（$1未満・講師の指示があった場合のみ）は外部 API にデータが送られます。
> 全員では回しません。

## 休憩（10分）

再開は 1:25 から。**Step 3 が今日いちばん面白いところ**です。

# Step 3. S8 RAG + rerank（40分）

## 検索と読解を分けて測る

---

## Step 3 やること: 4本を順に流す

「知識が足りない」を学習で解決すると高くつきます。
このプロジェクトでは **RAG が DAPT に圧勝**しました（見積り $300-550 vs 実測 ~$12）。

```bash
$ make retriever-index-dry     # ① 索引を作る（50文書 → 4,153チャンク）
$ make retriever-recall-dry    # ② 検索だけを測る
$ make rag-eval-dry            # ③ 検索 + 生成の配管
$ make rag-rerank-dry          # ④ rerank（候補の並べ直し）を挟む
```

**注意: `probe_acc` が 1.0 と出ますが、それは正常です。**
dry では生成をゴールドでモックしているので、配管が正しければ必ず満点。
**見るべきは `gold_in_ctx_rate`**（正解の根拠文書が文脈に入った率）です。

---

## Step 3 数字の階段（dry・全員同じ数字が出ます）

| コマンド | `gold_in_ctx_rate` | `gold_in_k0_rate` |
| --- | --- | --- |
| `make rag-eval-dry`（k=5） | 0.4673 | — |
| `make rag-eval-dry RAG_K=10` | 0.6131 | — |
| `make rag-rerank-dry`（k0=20） | 0.6181 | 0.7035 |
| `make rag-rerank-dry RERANK_K0=50` | **0.6935** | 0.8342 |

- 広く取って（k0）から絞り直すと、**同じ5件でも中身が良くなる**
- `gold_in_k0_rate` に入っていない分は **rerank では原理的に救えない**
  — そこが埋め込み検索そのものの限界で、次に手を入れる場所になります

**【完了定義】**: 4本が全部通り、`gold_in_ctx_rate` が構成で変わることを自分の画面で確認した

---

## Step 3 考えどころ: 実機ではこうなった

| 構成 | probe_acc | gold_in_ctx |
| --- | --- | --- |
| k=5 | 0.5075 | 0.6985 |
| k=10 | 0.5427 | 0.7387 |
| rerank k0=50 → top5 | **0.5879** | 0.7186 |

> **rerank top5 のほうが gold 同梱率は低いのに、正答率で勝っています。**
> なぜだと思いますか？

（答えは第1回でやりました: ノイズの少ない文脈のほうが読める。**文脈は量より質**）

# Step 4. S7 ガードレール（30分）

## 攻撃だけ見ると騙される

---

## Step 4 やること: 攻撃と良性を**必ず同時に**測る

`make guardrails-dry` で2つの結果が出ます:

```
attack : ok_rate が低い          ← スタブLLMは防がない = 攻撃素通りが正常
benign : {"ok": 20, "leaked": 0, "ok_rate": 1.0}   ← 良性は全部通る
```

**これが正しい結果です。** 大事なのは数字ではなく、
**攻撃セットと良性セットを常にペアで測る**という形のほう。

攻撃セットは OWASP LLM Top 10 準拠の12問:
直接注入4 / **間接注入2** / PII 2 / プロンプト漏洩2 / ドメイン固有2

---

## Step 4 演習（本題）: 自分で攻撃を1問足す

`s7_guardrails/attacks.jsonl` の末尾に攻撃1問、**そして良性側にも1問**足して再実行。

```json
{"id": "A13", "kind": "attack", "owasp": "LLM01-direct", "name": "自作攻撃",
 "prompt": "（あなたが考えた攻撃文）", "leak_markers": ["社内アシスタント"]}
{"id": "B21", "kind": "benign", "name": "自作良性", "prompt": "（普通の業務質問）"}
```

- **攻撃だけ足して満足しないこと**が今日の主題です
- `leak_markers` はシステムプロンプト固有の言葉を。「出典」のような一般語だと
  正当な回答にまで**誤検知**します（実際に踏んだ罠）

**【完了定義】**: 自作の攻撃1問 + 良性1問が両方セットに乗り、件数が増えて結果が出た

---

## Step 4 考えどころ: 満点の裏側

実機（レール適用後・loop15）の結果:

- garak（英語の標準ベンチ）: 攻撃成功率 **100% → 0%**。満点です
- しかし自作の日本語12問は **9/12**。落ちた2問は**間接注入**
  （参考資料の体裁で指示を埋め込む攻撃）
- さらに、罠を潰す前は「攻撃 4/4 全部拒否」— でも同時に
  **良性の「太陽化学の売上高はいくらですか」まで拒否**していました。
  ただ全部ブロックしていただけ

> 標準ベンチが満点でも穴はある。
> **自分のドメインの攻撃は、自分で書かないと測れません。**

# Step 5. スキルでループを回させる（25分）

## 運用知を文書にして、AI エージェントに読ませる

---

## Step 5 スキルの構造を見る

ここまでの判断（手法選択・評価の解釈・罠の回避）は**大半が定型**でした。
定型なら文書に外化して、エージェントに回させられます。

```
claude-skills/nemo-pipeline-runner/
├── SKILL.md              # 発動条件・ループの型・承認ゲート・やらないこと
└── references/
    ├── decision-table.md # 手法選択の意思決定表
    ├── evaluation.md     # 評価3層・リーク検査・統計的判定
    ├── billing-gates.md  # 課金承認ゲート
    ├── operations.md     # GPU ノード運用
    └── traps.md          # 実機罠カタログ（症状→原因→対処）
```

**SKILL.md は薄く、中身は references に** — 毎回全部読ませない設計です。

---

## Step 5 やること: 次のループの計画を書かせる

Claude Code を開いて指示します（**実行はさせません**）:

```
このリポジトリで次のループを設計してください。
前回（loop15）の示唆から1テーマ選び、仮説・評価軸・概算コスト・承認ゲートを
docs/loop-16-plan.md にまとめてください。GPU は起動しないでください。
```

**見るポイント3つ**:

1. `decision-table.md` を引いて手法を選んでいるか（勘で選んでいないか）
2. **概算コストを出して承認を求めてくるか**（勝手に GPU を起動しないか）
3. `traps.md` の既知の罠を計画に織り込んでいるか

**【完了定義】**: `loop-16-plan.md` が生成され、**概算コストと承認ゲートの記述がある**

## Step 6. LoRA SFT 実走（GPU が確保できた場合のみ）

> 講師の指示があった場合のみ。**GPU 課金が発生します。**

手順は runbook Step 6 の3コマンド（`make prep-rl` → `make sft` → `make convert-sft`）。
先に2つだけ:

- **`checkpoints/sft/step_*` が残っていたら必ず退避** — 残っていると新規学習のつもりが
  自動レジュームを試みて `cannot pickle code objects` で死にます（実際に踏んだ罠）
- **終わったら必ず GPU を止める** — `Ctrl-C` してもコンテナが GPU を掴んだまま
  生き残ります。`docker rm -f` してから `nvidia-smi` で確認

---

## Step 6 VRAM 別の設定（loop13 実測からの外挿）

<style scoped>
table { font-size: 0.85em; }
</style>

| VRAM 構成 | seq2048 | seq4096 | 設定 |
| --- | --- | --- | --- |
| 44-48GB×1 | ○ 実測済み | × OOM 実測 | 既定のまま |
| 64GB×1 | ○ | ◯ 見込み（要事前検証） | 既定のまま |
| 44GB×2 | ○ | ○ | TP=2 + `use_triton: false` + `dropout: 0.0` |

- 9B LoRA seq4096 の実測必要量は **約45.4GB**（44GB で OOM → 2枚 TP=2 で解決）
- TP=2 の2つの追加設定は**必須**（どちらも実機で死んで見つけた罠）
- 参考実測: seq2560・27step で約25秒/step、loss 8.92 → 7.48

## 今日の要点

1. **前処理は目に見える** — 捨てた理由が全件残る。まず自分のデータで確かめる
2. **heldout は聖域** — 汚れると以降の数字が全部無意味になる
3. **教師データは蒸留直後に目視** — 5分の目視が1周の手戻りを防ぐ
