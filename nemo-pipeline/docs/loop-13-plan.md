# ループ13 設計書 — grounded QA SFT（RAG読解ミス23ppの回収）

作成: 2026-08-08（設計フェーズ・課金操作なし）。承認ゲート通過後に実装・実行へ進む。

## 1. 目的と位置づけ

loop12 の総括（docs/loop-12-report.md §2）で、RAG probe 199問の誤答が2層に分解された:

- **検索ミス 30%**: gold が top5 文脈に入らない（recall@5 0.6985）
- **読解ミス 23pp**: gold を文脈で渡しても誤答（gold_in_ctx=1 の読解正答率 ~68-72%。
  この値は probe-50プール/全量プールの両方で安定 = 検索難度に依らない base の素の読解力）

→ loop13 は **読解ミス 23pp** を標的にする。仮説:

> **base は「RAG文脈から短答を抽出する」形式ができていない。目標形式と一致するデモ
> （RAG文脈+質問→短答）で LoRA SFT すれば、知識を注入せずに読解正答率が上がる。**

decision-table.md での手法検証:

- 「タスクの形式ができない × 目標形式と一致するデモ」→ **SFT**（loop1-7 実証行）に合致。
  デモは教師で新規蒸留する（loop9 r1 の教訓: 形式不一致デモの流用は逆効果）
- GRPO を第一選択にしない理由: 読解正答率 0.68-0.72 は「時々正解」帯域だが、probe 採点は
  二値（数値相対誤差1%/文字列包含）で**連続部分点報酬が組めず**、GRPO 3点セット (b) が欠ける。
  SFT が刺されば loop14 以降で仕上げ候補として再検討
- 検索側（rerank NIM）を後回しにする理由: recall@10 0.7387 のため top10→5 rerank の上積みは
  +4pp どまり（効かせるなら k=100 からで別設計）。読解側の 23pp が先

上限の明示: 検索は今回いじらないので、probe_acc の理論上限 ≈ gold_in_ctx_rate 0.6985 × 読解正答率。
読解 0.85 なら probe_acc ~0.59、0.90 なら ~0.63。

### 教材としての目標

新規 NeMo コンポーネントはなし。**既消化コンポーネントの連結**が主題:
S8 Retriever（loop12）で学習データを作り、NeMo-RL SFT（loop1-9）で学習し、
評価3層（loop10）で判定する — 「知識=RAG / 形式=SFT」の役割分担を実走で完成させる。

## 3. 学習データ設計（ここが本丸）

| 設計項目 | 決定 | 根拠 |
| --- | --- | --- |
| 出典文書 | corpus_train のうち **probe-50 を除く** 2,480文書からサンプル（~500文書目安） | 評価文書と学習文書を分離（open-book でも質問レベルのリークを構造的に排除） |
| QA生成 | `probe_qa.py --generate` を流用（4問/文書 → **~2,000問**） | 実績ある生成規約・追記jsonlで中断再開可 |
| 文脈 | **実検索**（EBS残置インデックス + embedding NIM）で top5 | 学習と評価の形式・分布を完全一致させる（loop8/9 敗因「学習と評価の非対称」対策）。プロンプト構築は `probe_qa.py --rag` と同一コードを import して共有 |
| gold_in_ctx=0 の扱い | 「記載なし」回答の教師例として **15-20% を上限に混入**、超過分は破棄 | 検索ミス時の誠実な挙動を教える。ただし loop1 罠（全件記載なし）があるためサンプル検査 must |
| 思考モード | 学習データは思考なし短答。評価も `enable_thinking: false` | 学習と評価で設定を揃える（loop8 教訓） |
| ベース | base（Nemotron-Nano-9B-v2-Japanese）に LoRA | dapt10 は形式退行あり（loop10②）で土台に不利。loop12 の rag199 も base 実測 |

想定規模: 実効 answerable ~1,400問 + 記載なし ~300問 ≈ 1,700例 × (文脈~3-4k字+短答)。
LoRA 1-2 epoch で十分小さい（loop9 SFT 実績から数時間以内）。

## 4. パイプライン設計

- `build_grounded_sft.py` + `sft_grounded.yaml` + Makefile ターゲット + ユニットテスト
  （プロンプト共有・gold_in_ctx分岐・記載なし上限・リーク検査の回帰テスト）

  「形式系（冗長・抽出スパンずれ・正規化）/ 能力系（複数チャンク統合・計算）」に分類
- **進行判断チェックポイント**: 形式系が過半なら P2 へ。能力系が過半なら SFT の伸びしろは
  小さいと判断し、目標値を下方修正 or テーマ再選定をユーザーに提案（ここで止まるのも成果）

### P2 教師QA生成（ゲートC: API課金）

- リーク検査を通す（学習QA vs probe 199問、出典文書の分離検証）

## 5. 評価設計（3層の loop13 適用）

| 層 | 物差し | 判定 |
| --- | --- | --- |
| ① 読解（主役） | gold_in_ctx=1 サブセットの正答率（n≈139・SE±0.04） | base ~0.68 → **≥0.85 で成功**。0.75-0.85 は部分改善（誤答再分類へ） |
| ② 全体 | rag199 probe_acc（n=199・SE±0.035） | 0.4724 → **≥0.55 で成功**（SE を明確に超過）。gold_in_ctx_rate が 0.6985 のまま不変であることも確認（検索配管の同一性チェック） |
| ③ 非退行 | 既存 eval（BASELINE=base）+ closed-book probe | 既存 eval が SE 内（LoRA なので full-param DAPT より忘却リスクは小さいが**測るまで信じない** — loop10 教訓）。closed-book は ~0.04 のまま（SFT は知識注入ではない、の確認） |

- リーク規律: probe 199問・probe-50文書は学習・プロンプト例に一切使わない。heldout（finqa/analysis）
  は非退行測定のみ（従来どおり学習不使用）
- ①と②の分離は loop12 と同じ肝: ②が伸びなくても①が伸びていれば「SFT は機能・律速は検索」と
  切り分けられ、rerank/クエリ拡張（loop14候補）に根拠が移る

## 7. リスクと撤収基準

- **誤答分類で能力系が過半**（P1）: SFT では読解 23pp の大半は取れない見込み → 進行前に
  ユーザーへ再提案（目標下方修正 / rerank へ転進 / クローズ）。**課金前に分かるのがこの設計の要点**
- **教師QAの品質不良**（P2 サンプル検査で整合率低・記載なし過多）: 生成規約を1回だけ調整して
  再サンプル。それでも不良なら中止（全量課金前に止まる）
- **①改善 × ③退行**（形式崩壊・忘却）: LoRA rank/lr 弱め or 既存SFTデータ混合で**1回だけ**再走。
  それでも退行なら「grounded SFT は既存能力とトレードオフ」を実測結論として総括（負の結果も成果）
- **①改善 × ②横ばい**: 検索律速の実証 → 成功扱いで総括し、loop14 を検索側（rerank k=100）に設定
- **スポット中断・SSMタイムアウト**: QA生成・検索・SFT とも追記/checkpoint 再開可能な既存設計を踏襲
