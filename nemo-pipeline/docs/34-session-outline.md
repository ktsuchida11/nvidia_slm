# 34. 第1回セッション構成（座学 + $0デモ）

対象: 社内エンジニア。**LLM の実務経験は前提にしない**。
時間: 90分（デモ10分・Q&A込み）。スライド本体は `36-slides.md`。

## 0. このセッションのゴール

聴衆が持ち帰るものを3つに絞る。全部を教えようとしない。

1. **NeMo の各ツールが「何を変える道具か」を言える** — 知識・検索・分布・形式・仕上げ・安全の6役
2. **手法を選ぶ前に base を測る、という順序を体が覚える** — ここを飛ばした失敗を実測で見せる
3. **この一周を AI エージェントに回させる形（スキル）がある**と知る — 第2回でそれを触る

裏目標: 第2回ハンズオンへの参加動機をつくる。そのため**デモは必ず動く $0 のものだけ**にする。

## 1. ストーリーの一本線

> **手法は目的で選ぶ。選び間違えると、何もしないより悪くなる。**
> そして「良くなった」は測って初めて言える。実測はしばしば直感を否定する。

この線に乗らない話（モデルアーキテクチャの解説、論文サーベイ、NeMo の全機能紹介）は入れない。

## 3. 章ごとの「主張 → 裏づけ」対応

**章2（手法選択）** — 主張は3つ、全部が失敗の実測で裏づく。

| 主張 | 実測 |
| --- | --- |
| base が既に強いタスクへの SFT は壊す | loop9 r1: finqa 0.7823 → **0.163**、既存 analysis 0.836 → **0.115** |
| 暗記済みデータの GRPO は信号ゼロ | loop8: GRPO 訓練セットが SFT と完全同一 → グループ内 advantage=0 |
| 1epoch の生テキスト DAPT は知識を入れない | loop10: probe **0.0402 = base と完全同点**（ppl は −10.6% 改善） |

**章3（コンポーネント実測）** — 1コンポーネント1スライド、必ず「数字 → 解釈」の順。

| コンポーネント | 見せる数字 | 解釈 |
| --- | --- | --- |
| Curator / S1 | 6件 → kept 2 / rejected 3 / fuzzy 1 / PII 2種（デモと同じ） | 前処理は目に見える |
| S2 蒸留 | loop1: generation 学習データ **17/17件が「記載なし」** | データの欠陥は評価前に見つかる |
| S3 DAPT | ppl −10.6% ↔ probe 同点 ↔ 既存評価 −0.115 | 1指標で合否を語らない |
| S4 SFT | loop1-7 で analysis 0.0 → 0.821、loop13 は読解 +5.1pp ↔ analysis −14.8pp | 効くが、他を壊す |
| S5 GRPO | KL無し net −10 → KL 0.02 で net **+1** | KL は必須。ただし天井 |
| S8 RAG | closed-book 0.0402 → **0.4724**（11.8倍）を **~$12** で | 知識は RAG が先 |
| S8 rerank | k=10 0.5427 < rerank top5 **0.5879** | 文脈は量より質 |
| S7 Guardrails | garak 92.8% → **0%**、しかし自作12問は 9/12 | 標準ベンチは満点でも穴はある |

**章4（評価設計）** — 「なぜそこまでやるか」を1枚で。

- 3層分離（held-out loss / probe / 非退行）は loop10 で**それぞれ違う答えを返した**＝分ける意味があった
- リーク検査は loop10 で**223文書の実リークを検出**。検査なしなら評価は汚染されていた
- 差は SE と比べる（n=300 で ±0.02）。SE 内は「改善」ではなく「同等」
- 課金前に dry で配管を通す（デモで見せるのがこれ）

**章6（スキル化）** — 実物を見せる。`SKILL.md` の6ステップと承認ゲート表をそのまま投影する。
「AI が勝手に GPU を回さない仕組み」を強調する（聴衆が最初に不安に思う点）。

## 4. $0デモ台本（10分・全て DevContainer で実測済み 2026-08-27）

画面は**ターミナル1枚**にする。1コマンド1メッセージ。イメージのビルドは要らない
（素の `python:3.12-bookworm` で全部通る。`35-handson-plan.md` §1 で実測確認済み）。

### デモ1: S1 キュレーション（2分）— 「前処理は目に見える」

```bash
make curate-demo      # data/demo_raw の6件サンプルを投入済みの状態から
cat data/demo_curated/stats.json
```

> **`make curate` ではなく `make curate-demo`**。開発機の `data/raw/` には EDINET 実データが
> 2,530件入っているので、`make curate` を叩くと全量が対象になり **kept 2530** が出てしまう
> （台本の数字が再現しない上に `data/curated/` を再生成してしまう）。
> `curate-demo` は `data/demo_raw` → `data/demo_curated` に隔離されている。

実測出力（このまま出る）:

```json
{"kept": 2, "rejected": 3, "fuzzy_dropped": 1,
 "pii_masked": {"EMAIL": 1, "PHONE_JP": 1}, "by_domain": {"finance": 1, "general": 1}}
```

`rejected.jsonl` を開いて理由を読み上げる: `exact_dup` / `too_short` / `license:cc-by-nc`。
**言うこと**: 「6件入れて2件しか残らない。捨てた理由が全部記録に残る。これが再現性の土台」。

### デモ2: 評価の配管検証（2分）— 「課金する前に配管を通す」

```bash
make eval-dry
```

`"n": 70, ... "pass": true` と全指標 1.0 が出る。
**言うこと**: 「モデルは1回も呼んでいない。ゴールドをそのまま答えにして、採点器と閾値の配線だけを確かめている。
本番で 0.0 が出たとき『バグか実力か』で悩まないため」。

### デモ3: ガードレール（3分）— 「攻撃だけ見ると騙される」

```bash
make guardrails-dry
```

attack の `ok_rate` が低く、benign が `1.0` で出る。
**言うこと**: 「スタブは何も防がないので攻撃は素通り。逆に良性は全部通る。
実機では**この2つを同時に見る**。攻撃だけ見て満点だと喜んだら、実は全部ブロックしていた——というのを実際にやりました」。
ここで loop15 の「良性 0.0 → 0.85」のスライドに戻る。

### デモ4: RAG + rerank の配管（3分）— 「検索が効いているかを分けて測る」

```bash
make rag-rerank-dry
```

実測: `probe_acc 1.0`（生成はゴールドのモック＝配管が正しい証拠）、
`gold_in_ctx_rate 0.6181`, `gold_in_k0_rate 0.7035`。
**言うこと**: 「正答率が 1.0 なのは配管確認だから。見るべきは gold_in_ctx。
**正解文書を渡せているか**と**渡した上で読めているか**を分けて測る。実機ではこの分離が
『次に何を直すか』を直接教えてくれた（検索ミス30% / 読解ミス23pp）」。

### デモの失敗に備える

- ネットワーク不要・GPU不要・API キー不要。**Docker さえ動けば全部通る**
- それでも落ちたら: 実行済みの出力を貼ったスライド（`36-slides.md` 付録）に切り替える
- 使う Python イメージが手元に無いと全部落ちる → **前日に `docker pull python:3.12-bookworm`**
  （`hostpath.mk` の `PY_IMG` がそれを指していることも確認する）

## 5. 想定質問と答え（準備しておく）

| 質問 | 答えの骨子 |
| --- | --- |
| 「結局いくらかかったの？」 | 15周で **~$395-410**。内訳の最大は loop9 の ~$200（手法選択ミスによる再走）。ゲート運用でそれ以降は1周 $10-50 に収まった |
| 「自社データでやるには？」 | S1 のライセンス/PII ゲートを通すのが最初。機微データの扱いは `05-proprietary-data-design.md` |
| 「9B ってどのくらいの GPU が要るの？」 | LoRA SFT は seq2048 なら L40S 1枚（44GB）。**seq4096 は OOM して 2枚 + TP=2 が必要**（loop13 実測） |
| 「RAG があるなら学習は要らない？」 | 知識は RAG が正解。ただし**形式**（JSON を出す・短答で答える）は RAG では変わらない。そこが SFT の役割 |
| 「AI に任せて暴走しない？」 | 課金・削除・外部送信は全部**人間の承認ゲート**。スキルの `やらないこと` に明記して、実際に15周それで運用した |
| 「Nemotron じゃないとダメ？」 | パイプラインはモデル非依存。ただし**思考モードの扱い**はモデル固有で、ここで2回踏んだ（loop8・loop15） |
