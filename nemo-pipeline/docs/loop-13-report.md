## 1. 問いと答え

**問い**: RAG の読解ミス23pp（gold文脈を渡しても誤答）は、目標形式と一致するデモ
（RAG文脈+質問→短答）の LoRA SFT で回収できるか？

| 層 | 判定値（#65改訂後） | 実測 | 判定 |
| --- | --- | --- | --- |
| ① 読解（gold_in_ctx=1, n=139） | 0.676 → ≥0.78 | **0.7266**（+5.1pp） | **部分改善**（0.72-0.78帯） |
| ② rag199 probe_acc (k=5) | 0.4724 → ≥0.52 | **0.5075**（+3.5pp） | 未達（SE±3.5ppの保留帯） |
| ②' RAG_Kスイープ（参考） | — | k=8: 0.5377 / **k=10: 0.5427** | k=10でベースライン比 **+7pp** |
| ③ 非退行（heldout n=70・base同条件再測定） | SE内 | **analysis_match −14.8pp / schema_valid −9.8pp** | **不合格（形式退行）** |
| ③' closed-book サニティ | ~0.04のまま | 0.0452（base 0.0402・SE内） | 合格（知識注入ではない） |

**答え**: SFT は機能する（改善+7問は全て読解帯、gold_in_ctx_rate は base と完全一致 = 配管同一）が、
**「短答のみ・説明不要」の形式学習が既存の分析タスク（JSONスキーマ出力）を壊す**。
LoRA・lr 2e-5・2epoch という弱め設定でも、loop10 の full-param DAPT と同型の形式退行が起きた。

**運用解（本ループの主成果）**: LoRA はアダプタなので**マージせずタスクで配信を切り替える** —
分析=base / RAG-QA=sft13。単一モデルに両立させる必要はそもそもなかった。
「知識=RAG / 分布適応=DAPT / 形式=SFT」の役割分担に**「形式SFTはアダプタ単位で分離」**が加わる。

## 2. P1 誤答分類 → 目標改訂（$0 チェックポイントの成果）

rag199 誤答45問を P2 詳細と突合＋文書全文照合で分類（詳細 #65）:
スタイル3 / **検索粒度系14**（P2の小索引では正解=SFTで回収不能）/ 誤値抽出12 / 表合成答8 / 記載なし宣言8。
形式系が3問のみ＝§7発動 → 目標を 0.85→0.78 / 0.55→0.52 に改訂し RAG_K スイープを追加してから課金。

**答え合わせ**: SFT の実際の回収は+7問 — 分類時の見積り「+9〜14問」の下端弱。
検索粒度系14問は k=10 で +7問ぶん回収（0.5075→0.5427）— **分類の2軸（読解/検索）がそのまま改善の2軸になった**。

## 3. 学習データ（P2・教師API ~$15）

- 500文書（probe-50除外・決定的サンプル）× 4問 = 2,000問 → **真正リーク1問を除去**して1,999問
  - リークの型: **同一企業の別年度有報**が学習/評価プールに分かれ同一QAが生成される。doc_id 分離では
    防げない（正規化質問照合が捕捉）。厳密には会社レベル分離が必要 — 今回は1件のため除去で対応
- 実在フィルタの設計バグを単価実測で発見（#66）: 有報の表は「セル値+ヘッダ単位」で答えが合成され
  逐語不在（52問中21問）→ 逐語包含のままだと**一番教えたい表読解の学習例を捨てる** → 数値トークン照合に緩和
- grounded-build 実測: 1,999問 → **学習例 1,329**（answerable 1,090 / 記載なし 239=18%上限どおり /
  抽出不能271は破棄）。gold_in_ctx 率 68.1% ≈ rag199 の 0.6985（学習と評価の検索分布が一致）

## 4. 実機の罠（ゲートAで踏んだ4件 + 評価1件）

1. **ディスクフル**: NeMo-RL イメージ pull 中に枯渇（root 98%）。nemo:25.04（92.4GB・DAPT用）と
   ビルド不良 vllm v0.25.0（36.4GB）の削除で 128GB 回復。**未使用の巨大イメージは撤収時に棚卸しする**
2. **seq4096 は L40S 44GB×1 で OOM**（9B LoRA・activation checkpointing 込みで backward 死）→
   `gpus_per_node: 2` + `tensor_parallel_size: 2`
3. **TP>1 で `use_triton: true` が assert 死**（NeMo-RL: Triton is not supported when TP>1）→ false
4. **TP>1 で LoRA dropout が実行時死**（`aten.native_dropout with Partial is not supported`）→ 0.0
   - 2-4 は「TP=2 切替の3点セット」。sft_grounded.yaml に反映済み（#68）
5. **旧 baseline と n 不一致**: 評価セットが loop9 時点（n=300）から変わり相対比較不能 →
   **base を同一 run 条件で再測定**（base13_reg）してから比較。baseline は評価セットの世代とペアで管理

SFT 本走: 78 step（39/epoch×2）・66s/step・loss 0.98→0.031。TP=2 の checkpoint/変換/配信も問題なし。
